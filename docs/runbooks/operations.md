# 日常运维手册

## 健康检查

| 路径 | 访问边界 | 含义 |
|---|---|---|
| `/health/live` | 匿名 | 进程可响应，不检查数据库或外部服务 |
| `/health/ready` | 仅服务器回环 | 校验数据库目标、Schema version 2 和必需对象 |

健康响应只返回总体状态，不输出连接信息、表名、异常或秘密。IIS 外部探针只使用 live；ready 由服务器本机或受控运维任务访问。

```powershell
Invoke-WebRequest https://127.0.0.1:<port>/health/live -UseBasicParsing
Invoke-WebRequest https://127.0.0.1:<port>/health/ready -UseBasicParsing
```

## 关键观测

- 结构化业务审计是强制门禁，OpenTelemetry 不是审计替代品。
- 关注登录失败与锁定、Turn 成功率、并发冲突、模型/工具调用次数、外部调用失败、超时、预算拒绝和维护任务结果。
- 指标标签不得包含姓名、手机号、企业名、凭据、原始错误或可对外关联的会话 ID。
- OTLP 不可用时业务可以继续；审计预写失败时模型、工具和法大大调用必须失败关闭。

## 备份与恢复

同一恢复点应包含：

1. `FddAgent*` Schema version 2 数据库备份与日志链。
2. Data Protection 密钥目录、ACL 和应用池身份说明。
3. 已验收发布包、Git 提交、SDK、锁文件、Prompt/工具 Schema 版本和无秘密配置清单。
4. IIS 站点、HTTPS 绑定、应用池和服务器配置的可审计导出。

至少季度在隔离的非生产目标执行恢复演练，校验 readiness、本地账号登录、会话读取和审计关联。不得连接其他业务数据库，不得覆盖既有数据。

## 数据生命周期

- 诊断原始载荷默认关闭；如未来启用，必须另行审批、加密并设置不超过 7 天的 TTL。
- 归档是可恢复的软删除状态：会话从“当前”移入“已归档”，内容只读，恢复后可以继续查询。
- 归档会话正文默认保留 180 天；仅在 `DataLifecycle__Enabled=true` 时执行到期清理，结构化审计按企业审计政策保留。
- `DataLifecycle__Enabled=true` 时，单实例后台任务按配置分批处理，并写 `FddAgentMaintenanceRun`。
- 启用清理前必须备份并在小批量数据验证；禁止手工删除审计或把清理脚本指向非本项目表。

## 变更流程

每次模型、Prompt、工具 Schema、框架、策略或数据库适配变更都必须：

1. 固定版本并更新 ADR 或变更记录。
2. 执行 locked restore、Release 零警告构建和全部默认离线测试。
3. 执行当前 Agent 36 案例绝对门禁，要求 100% 通过和零安全违规。
4. 如涉及本地 Lab，只执行显式批准的只读 readiness；插入型 probe 需另行授权。
5. 在隔离环境验证发布包秘密扫描、登录、会话、SSE 和错误路径。
6. 单实例回收应用池并观察 ready、审计完整性、错误率和资源使用。

## 故障原则

- 模型或法大大失败：返回稳定安全错误，不降级为绕过策略的直接调用。
- 数据库或审计失败：停止新 Turn，不继续模型或外部调用。
- Data Protection 密钥丢失：现有 Cookie 失效，恢复密钥或要求重新登录；不得临时关闭 Cookie 保护。
- 配置或秘密疑似泄露：立即轮换，保留审计证据，重新发布干净包，不在工单中粘贴秘密。
