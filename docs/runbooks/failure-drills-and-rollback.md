# 故障演练与回滚手册

所有演练使用合成账号和数据，在隔离环境执行。不得把真实秘密写入脚本、命令输出或报告，不得连接 PSP 数据库。

## 必做演练

| 场景 | 注入方式 | 预期行为 | 恢复验证 |
|---|---|---|---|
| 数据库不可用 | 临时阻断隔离环境数据库连接 | ready 为 503；Turn 启动或审计预写失败；模型和法大大请求计数为 0 | 恢复连接，ready 为 200，审计链完整 |
| 模型网关超时/5xx | 使用失败替身或受控网关规则 | 返回稳定 Agent 错误；不泄露 provider 正文或 Key；调用预算不超限 | 恢复网关，执行一条合成查询 |
| 法大大超时/5xx | 使用 Fake Handler 或获准沙箱故障 | 证据为失败/部分成功，不把缺失证据写成否定事实；外部预写和终态存在 | 恢复后核对固定 GET 端点和审计 |
| 审计预写失败 | 测试替身拒绝 prewrite | 在 HTTP 请求发出前失败关闭，外部请求为 0 | 恢复审计存储，重新运行安全测试 |
| OTLP 不可用 | 停止隔离 Collector | 业务和结构化审计继续；不产生无限重试或敏感日志 | 恢复 Collector，确认新 Trace 可达 |
| Cookie/账号失效 | 重置密码或停用合成账号 | 现有 Cookie 下一请求返回 401，不调用模型或工具 | 启用/重新登录，新 Cookie 正常 |
| 并发 Turn | 同一会话同时发送两轮 | 一个 Turn 启动，另一个稳定返回 409；无重复助手消息 | 刷新会话后重新提交失败轮次 |

每次演练记录版本、时间、操作者、TraceId、预期与实际行为、恢复时间和改进项，但不记录 Prompt、原始工具结果、Authorization 或秘密。

## 应用回滚

1. 停止站点或应用池，保留当前发布目录和日志快照。
2. 确认回滚版本与当前 V2 Schema 兼容。仓库不提供破坏性 down 脚本。
3. 用已验收的前一发布包替换应用文件，不覆盖持久 Data Protection 密钥目录。
4. 恢复该版本的非敏感配置；秘密仍从服务器受保护来源提供。
5. 启动单实例应用池，依次验证 live、ready、登录、本人会话读取和一条合成只读查询。
6. 核对回滚期间没有未审计的外部调用，并记录回滚原因和后续修复计划。

## 数据库回滚

DDL 只人工执行且没有自动 down migration。若数据库变更必须回滚：

- 优先采用经评审的 forward-fix。
- 需要恢复时停止写入，使用变更前备份恢复到明确目标，并同步校验 Data Protection 密钥和发布版本。
- 不删除既有审计来“回到旧版本”，不在 PSP 库创建兼容对象。

## 升级处置

以下情况立即停止上线或回滚：秘密扫描命中、任一安全 Eval 违规、默认测试出现真实外连、ready 失败、Cookie 安全属性下降、工具/端点集合扩大、审计预写不再失败关闭，或 SQL 目标偏离已批准数据库。
